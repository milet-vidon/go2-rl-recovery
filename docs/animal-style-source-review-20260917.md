# Animal-style motion: checked primary sources and next boundary

Read on2026-09-17 while finite regressions run. This is source review, not a claim that the current Go2 policy implements or reproduces these papers.

[Learning Agile Robotic Locomotion Skills by Imitating Animals](https://xbpeng.github.io/projects/Robotic_Imitation/index.html) and its [author repository](https://github.com/erwincoumans/motion_imitation) use reference animal motion with robot retargeting and policy imitation. This supports collecting/retargeting actual motion for style; merely increasing our velocity reward or lateral-foot penalty is not the same method.

[Adversarial Motion Priors Make Good Substitutes for Complex Reward Functions](https://arxiv.org/abs/2203.15103) learns a style reward from reference motion and combines it with task reward. The [official implementation](https://github.com/escontra/AMP_for_hardware) targets Unitree A1 and legacy Isaac Gym, with reference data in its datasets folder. It is not a ready-made Go2/Isaac Lab checkpoint. Do not replace the working environment with its old dependency versions.

The [actual A1 configuration](https://github.com/escontra/AMP_for_hardware/blob/main/legged_gym/envs/a1/a1_amp_config.py) differs materially:42actor/48privileged observations, reference-state initialization, decimation6 and many ordinary shaping terms set to zero; AMP task/style mixing is explicit. Our native actor48,50Hzcontrol, standing/recovery geometry and preserved PPO checkpoints must not silently inherit those dimensions, reset distribution or reward removals. Copying the advertised command range would not prove actual fast running.

The [author motion loader](https://github.com/escontra/AMP_for_hardware/blob/main/rsl_rl/rsl_rl/datasets/motion_loader.py) explicitly converts PyBullet leg blocks FR/FL/RR/RL to Isaac Gym FL/FR/RL/RR, with joint positions, local toes, velocities and root state in separate blocks. Our Isaac Lab joint order is joint-type-major, not that leg-block order. A new Go2 loader needs named-joint permutation, quaternion/frame/time interpolation and forward-kinematics checks before training. A third-party summary of these indices is not adequate evidence.

Engineering next steps, NOT already implemented: preserve the validated recovery/zero-command behavior; first settle the common-physics retention and current all-axis posture tradeoffs. If a motion-prior branch follows, keep it isolated, review source and motion-data licenses separately, retarget reference toe trajectories to Go2, and validate moving and zero-command segments independently. Motion style must not force stepping while the user commands standstill. Compare against the current baseline at matched training budgets, preserve rejected runs, and require whole-episode videos and measured gait/heading/stop checks. Recovery still needs its own data and acceptance; a locomotion motion-prior paper does not automatically provide self-righting.

The [repository license](https://github.com/escontra/AMP_for_hardware/blob/main/LICENSE) points to separate asset/dependency notices. No external source, motion data or model has been copied into the portfolio during this review.
